# MAX Network — новости ИИ в один клик

Локальная редакция NeuroPulse: RSS → проверка конкретного события через Ollama → готовый новостной текст → MAX. Python 3.12+, Ollama `qwen2.5:3b`, `https://platform-api.max.ru`. Без внешних шрифтов/CDN.

## Обновление на Mac

Остановите сервер через **Ctrl+C**, затем:

```bash
cd ~/Downloads/MAX-Network-new
git pull --ff-only
./start.command
```

Откройте `http://127.0.0.1:8000`, обновите Safari через **⌥⌘R**. Ваши `.env`, источники, каналы, история и черновики сохраняются. Перед миграцией скрипт создаёт SQLite-бэкап в `backups/`.

## Ежедневное использование

**Каналы → «Выложить 1 новость»**. Один раз укажите Chat ID своего MAX-канала. Бот должен иметь права отправки; `MAX_TOKEN` берётся из существующего `.env`.

Кнопка выбирает наиболее свежую подходящую новость из проверенной очереди. Если очереди нет, запускает сбор и подготовку. При подготовке одной новости приоритет отдаётся новостным лентам; обработка может остановиться после первого подходящего свежего события. Будет отправлен **ровно один** пост. Непроверенная новость или случайная статья ради заполнения канала не отправляется. Если подходящих событий нет, панель объяснит причину. Повторное нажатие во время задания блокируется.

- Сбор и оценка запускаются автоматически после старта сервера и каждые 15 минут. Новая RSS-лента также запускает подготовку. Отдельно нажимать «оценить» или «перегенерировать» не требуется.
- Для стандартного ИИ-канала подключаются новостные RSS Хабра, iXBT и 3DNews. Статус доступности и ошибки каждой ленты видны в источниках; старые источники не удаляются. Прежние пользовательские источники сохраняются. В общей ленте бывают темы вне ИИ — они должны отсеиваться редактором.
- Ручная кнопка работает и при выключенном расписании канала. Флаг фоновых публикаций не блокирует непосредственную отправку по вашему нажатию.
- Текст публикуется **без строки «Источник» и ссылки на статью**. Под новостью автоматически добавляется жирная кликабельная подпись **NeuroPulse | Нейросети и ИИ**, ведущая на `https://max.ru/channel_neuropulse`. URL исходного материала хранится в базе и доступен в редакторе.
- Изображение из RSS прикрепляется автоматически. Галочки подтверждения прав нет. Чтобы отправлять конкретный пост без картинки, очистите URL. Открытая доступность изображения не означает автоматического разрешения на любое использование; подходящие материалы выбирает владелец канала.
- Редактирование сохраняется автоматически, включая закрытие редактора. Проверка изменённого текста также автоматическая. Кнопка публикации дожидается сохранения и проверки, не просит нажать «Сохранить» и не показывает дополнительное подтверждение отправки.
- Удалённый черновик скрывается, но отпечаток остаётся, чтобы новость не возвращалась при сборе.

На Intel Mac обработка новости может занять несколько минут. Оставьте Mac, Ollama и терминал сервера включёнными. `caffeinate -i ./start.command` предотвращает автоматическое засыпание, пока крышка открыта.

## Что проверяет редактор

Два этапа работы модели, с отдельной финальной сверкой текста:

1. **Событие.** Кто что выпустил, объявил, открыл или изменил? Подходит ли это каналу об ИИ? До оценки отдельный фильтр проверяет тему ИИ: обычные Android-приложения, прокси и сетевые утилиты не проходят только за факт нового релиза. Затем модель указывает конкретное событие и номера подтверждающих фрагментов, заранее выделенных приложением из RSS. Дословно переписывать цитату не требуется. Неверные номера вызывают одну попытку исправления, затем запись откладывается. Инструкции, обзоры статей, рассуждения и рекламные материалы не подходят.
2. **Готовая новость.** Полный русский текст без ограничения в 750 символов: что произошло и какие подтверждённые детали важны. Без «в статье автор рассказывает», ссылок и служебных инструкций. Текст дополнительно проверяется кодом и отдельным запросом к модели на соответствие утверждений исходному материалу. При ошибке генерации есть одна повторная попытка; некорректный результат не отправляется.

Для ручных правок модель отдельно сверяет текст с исходным материалом и сохраняет корректные правки. Ошибка или недоступность модели не считается одобрением. Для отправки одной выбранной новости и по расписанию требуется дата RSS не старше 48 часов, недавняя оценка, неизменённый проверенный текст, достаточная оценка (по умолчанию 75) и отсутствие дублей. Материалы без даты в этих сценариях не публикуются. Старые одобрения предыдущих версий сбрасываются на автоматическую проверку; опубликованные записи сохраняются.

Это **проверка по предоставленному RSS**, а не независимая проверка истины по всему интернету. qwen2.5:3b может ошибаться. Недостаточные описания не дополняются выдумками; материалы остаются без отправки.


## Постоянный резерв 10 готовых новостей

Цель редакции — **10 свежих проверенных новостей на канал**, дополнительно до 2 подготовленных запасных. На обзоре и карточке канала видно реальное состояние `7 / 10`, `10 / 10` и ошибки источников. В число готовых не входят устаревшие материалы, непроверенные тексты, низкие оценки, материалы вне ИИ или дубли событий.

За проход читается до **100 записей каждой ленты**, а не только первые 10. Сначала быстро сохраняются кандидаты и отсекаются явные материалы вне ИИ, затем свежие кандидаты последовательно проходят Ollama, пока не заполнится резерв. Для ограничения нагрузки за один проход проверяется до 60 кандидатов. Уже подготовленные тексты сохраняются в SQLite; повторная генерация при каждом запуске не нужна. Новые более свежие материалы могут вытеснять старые в запас.

После отправки запасная новость занимает свободное место, а редактор запускает добор. Источники обновляются каждые 15 минут; состояние резерва проверяется каждую минуту, при недоборе повторное пополнение выполняется не чаще раза в 5 минут. Для формирования резерва расписание публикаций включать не требуется — подготовка сама ничего не публикует.

Ошибка формата или подготовки одного поста больше **не останавливает проверку остальных**: он получает повторную попытку позже. Ошибка связи с Ollama приостанавливает модельный проход до восстановления. В панели видна конкретная причина, а не общий ложный отказ «не подтверждено цитатой».

Первое заполнение на Intel Mac может занять заметное время. Если в доступных лентах нет 10 свежих качественных событий или часть источников недоступна, будет показан честный недобор. Порог качества не снижается ради числа 10. Небольшая локальная модель не гарантирует безошибочную оценку всех материалов; проверка опирается на RSS, а не на независимый внешний фактчекинг.


## Подпись канала и длинные тексты

В **«Каналы → Настроить → Подпись под новостями»** доступны публичная ссылка MAX и текст подписи. Для NeuroPulse они уже заданы:

[**NeuroPulse | Нейросети и ИИ**](https://max.ru/channel_neuropulse)

В редакторе виден предпросмотр этой ссылки. Подпись добавляет приложение после проверки новости; Ollama не должна придумывать адрес или включать его в свой ответ. Для других каналов задайте их собственную публичную ссылку. Используется HTML-формат MAX с экранированием текста, поэтому символы `<`, `>` и `&` не превращают новость в разметку.

Ограничение **750 символов убрано** из генерации, проверки, редактора и API редактирования. Модель сохраняет существенные факты и контекст, не сокращая новость под искусственный размер. Бюджет генерации увеличен; если Ollama сообщает об обрыве по лимиту токенов, приложение повторяет генерацию с большим бюджетом и не публикует оборванный результат. Для модели из RSS передаётся до 12 000 символов исходного материала.

Текст сохраняется полностью. При отправке учитывается безопасный лимит сообщения MAX — 4000 UTF-16 единиц, консервативно вместе с HTML-разметкой. Если текст не помещается, он делится по абзацам/словам на последовательные сообщения без потери символов. Картинка прикрепляется к первой части, подпись — к последней. Это одна новость в очереди, даже если транспорт потребовал несколько сообщений. Короткая карточка в списке — только предпросмотр; полный текст доступен в редакторе и отправляется целиком.

Для каждой части сохраняются состояние и MAX message ID. Если первая часть уже отправилась, а следующая не прошла, вся новость не повторяется автоматически. Проверьте канал и либо дополните её вручную, либо удалите опубликованные части перед повтором. Панель требует отдельного подтверждения удаления частей только в этом аварийном сценарии.

## Публикации по расписанию

В настройках канала: интервал, дневной лимит, часы и часовой пояс. По умолчанию **60 минут, до 6 постов в день, 09:00–22:00 по Москве**. Автопостинг включается отдельно после успешной первой отправки через кнопку канала; сам по себе после обновления не включается.

Проверка расписания — каждую минуту. Выбирается свежий проверенный материал; пропущенные слоты не отсылаются залпом. Дневной лимит и интервал учитывают ручные посты. Непосредственное нажатие «Выложить 1 новость» — явная ручная отправка вне расписания. Кнопка общей паузы запрещает новые фоновые отправки; уже отправленный запрос она не отзывает.

Ошибка автопубликации отключает расписание канала и отображается в журнале. При таймауте или неизвестном результате повторная отправка блокируется: проверьте сам MAX и подтвердите результат в панели. Такой случай нельзя автоматически повторять, иначе возможен дубль. После перезапуска прерванная отправка также требует сверки.

## Первый запуск

1. Установите Python 3.12+ с [python.org](https://www.python.org/downloads/macos/), macOS universal2 подходит для Intel и Apple Silicon. Для Python 3.12 запустите `/Applications/Python 3.12/Install Certificates.command`. Скрипт находит официальный Python 3.12 без настройки PATH. При рабочем Homebrew подойдёт `brew install python@3.12`.
2. Установите и запустите [Ollama](https://ollama.com), затем `ollama pull qwen2.5:3b`.
3. Скачайте проект:

   ```bash
   cd ~/Downloads
   git clone https://github.com/YouTikc1/MAX-Network.git MAX-Network-new
   cd MAX-Network-new
   ```

4. Поместите свои сохранённые `.env` и `network.db` рядом с `app.py`. Скрытые файлы в Finder — **⌘⇧.** Не заменяйте старую базу пустой.
5. `chmod +x start.command && ./start.command`.

Локальная панель: `http://127.0.0.1:8000`, логин `admin`, пароль `ADMIN_PASSWORD` из `.env`. Не открывайте порт в интернет. Для одной базы используйте один процесс и один worker.

## Настройки и тесты

`.env` не изменяется и не хранится в Git. Нужны `ADMIN_PASSWORD` и `MAX_TOKEN`. Дополнительно: `OLLAMA_MODEL`, `OLLAMA_URL`, `MAX_API_BASE`, `NETWORK_DB_PATH`. Для изолированной разработки `NETWORK_BACKGROUND=0` отключает первоначальный фоновый проход; тесты используют также отдельную SQLite-базу и mock HTTP. Планировщик запускается при старте обычного сервера.

```bash
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m pytest -q
```

Проверяются два этапа модели, привязка к исходным фрагментам, блокировка текста-инструкции со скриншота, отсутствие ссылок в постах, автосохранение, первая отправка без флага расписания/галочки фото, выбор свежего события, отсутствие подходящей новости, двойное нажатие, расписание, лимиты, миграция старой базы, неизвестная отправка и защита от дублей. Реальные публикации в тестах не выполняются.


## Каналы Pulse

При первом запуске новой версии добавляются TechPulse (технологии), MoneyPulse (финансы), SportPulse (спорт) и BizPulse (бизнес). Старые каналы и история сохраняются. Для новых каналов заданы тематические RSS и присланные публичные ссылки MAX. В настройках можно изменить тематику, задание редактору, источники и подпись. Тематический отбор действует при сборе, оценке и публикации; ИИ-фильтр применяется только к NeuroPulse.

Чтобы узнать Chat ID, добавьте бота администратором в каждый канал, настройте MAX_TOKEN на сервере и нажмите «Каналы → Настроить → Узнать Chat ID у бота». Выберите нужный канал и сохраните настройки. Поиск читает одну доступную порцию событий бота через GET /updates и проверяет найденные каналы через GET /chats/{chat_id}; устаревший GET /chats не используется. Если нужного канала нет, опубликуйте в нём сообщение вручную в MAX и повторите поиск. Получение события зависит от настроек бота; при webhook или другом обработчике событий возьмите Chat ID из его событий. Поиск не меняет webhook, не передаёт marker для подтверждения событий и ничего не публикует. Найденные каналы сохраняются отдельно для текущего токена и перепроверяются при повторном поиске. Автопубликация включается отдельно после успешной ручной отправки.

Формат поста: первая короткая строка — жирный заголовок, пустая строка, основной текст, пустая строка, ссылка на соответствующий канал. Для ручных текстов отделяйте заголовок от основного текста пустой строкой. HTML в тексте экранируется. Из RSS сохраняется до 10 уникальных изображений и передаётся в attachments первого сообщения; видео пока не поддерживается. Реальную доставку альбома необходимо проверить на MAX с токеном бота. Очистка URL изображения в редакторе убирает все изображения поста.

### Облачная разработка без публикаций

```bash
cd /workspace/MAX-Network
python3 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir -r requirements.lock.txt
.venv/bin/python -m pytest -q
```

Для локального сервера задайте ADMIN_PASSWORD, NETWORK_BACKGROUND=0, отдельный NETWORK_DB_PATH и запускайте `.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000 --workers 1`. Не используйте рабочую базу для тестов. Для подготовки реальных новостей нужны запущенная Ollama и модель qwen2.5:3b; для публикации дополнительно нужны MAX_TOKEN и Chat ID. Тесты используют mock HTTP и ничего не публикуют.


Способ поиска Chat ID сверён с [официальным SDK MAX](https://github.com/max-messenger/max-bot-api-client-ts/tree/a5c40a09eed306405419ad2232e6b90466dd74d6/src/core/network/api/modules) (модули subscriptions и chats). Полный список каналов через GET /chats в этой версии API отсутствует. Токен и реальные события проверяются только на компьютере владельца; тесты приложения используют mock HTTP.
